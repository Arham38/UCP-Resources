1. Git Flow and branch naming

Git Flow is a workflow where every kind of work lives on a branch of a fixed type.

BranchCreated fromMerged intoNaming

feature/*developdevelopfeature/login, feature/PAY-42-checkout
release/*developmain and developrelease/1.1.0

Naming rules: use lowercase, separate words with -, and put the ticket number in the name if you have one.

git checkout -b develop main
git checkout -b feature/login develop
git checkout develop && git merge --no-ff feature/login
git checkout -b release/1.1 develop
git checkout main && git merge --no-ff release/1.1 && git tag v1.1
git checkout -b hotfix/crash main

3. Linear history and clean history

Linear history means git log --graph shows one straight line, with no diamonds or crossing lines. Clean history means every commit has a clear purpose, so there are no "wip" or "fix typo" commits. Rebase and squash (below) are how you get both.

git config --global pull.rebase true   # rebase instead of merging on pull
git merge --ff-only feature            # allow only straight-line merges

4. History rewriting: rebase and squash

Rebase replays your branch's commits on top of a new base. Commit IDs change (f1 becomes f1').

git checkout feature
git rebase main              # replay feature on top of main
git checkout main
git merge feature            # now a plain fast-forward

Squash combines several commits into one.

git merge --squash feature && git commit -m "Add login feature"   # way 1
git rebase -i HEAD~4                                               # way 2 (pick / squash)

The difference: rebase keeps every commit separate, squash makes them all one.

Golden rule: never rebase or squash a branch that has been pushed and that others are using. If you must, use git push --force-with-lease, never plain --force, because it will not overwrite work you have not seen.

5. Merge conflict

A conflict happens when both branches changed the same line of the same file. Git cannot decide which version is right, so it stops and asks you.

git merge feature            # CONFLICT
git status                   # look for "both modified" files
# open the file, remove <<<<<<<  =======  >>>>>>>, write the final line
git add index.html           # tell Git it is resolved
git commit                   # or: git merge --continue

If you panic, git merge --abort returns everything to the state before the merge. During a rebase, use git rebase --continue or git rebase --abort.
