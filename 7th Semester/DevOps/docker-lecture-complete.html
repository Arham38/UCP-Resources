Concept 1

What is containerization?

Containerization packages an application together with everything it needs to run: code, runtime (Node, Python), libraries and settings. The package, a container, runs the same way on any machine.

It solves the classic problem: "It works on my machine!" The app breaks on the server because the server has a different Node version or a missing library.

🍲
Send only the recipe to another city and the biryani tastes different: their masala, their rice, their stove. Send the whole cooked deg instead, and every guest gets exactly the same taste.

Container vs Virtual Machine

A VM virtualizes a whole computer with its own operating system. A container only isolates a process and shares the host's kernel. On Linux this uses namespaces (what a process can see) and cgroups (how much CPU/RAM it can use).

🍲
A VM is building a new kitchen for every deg: its own stove, gas line and staff. Containers are many degs on one big shared stove. The stove is the kernel.

Concept 2

Introduction to Docker

Docker is an open-source platform (2013) that makes containers easy to build, ship and run. Containers existed before (LXC); Docker made them simple for developers.

🍲
Build: cook the deg from the recipe. Ship: send the sealed deg to the market. Run: any kitchen picks it up, opens it and serves.

Hands-on: check your installation

# open Docker Desktop first and wait for "Engine running" $ docker --version $ docker version $ docker run hello-world
Concept 3

Docker architecture: Engine & CLI

Docker uses a client-server design. The CLI only sends requests. The daemon (dockerd) does the real work. Docker Engine = dockerd + REST API + CLI.

ComponentJobDeg kitchen
docker CLITurns your command into a requestOrder slip
REST APIThe format CLI and daemon talk inThe standard order format
dockerdManages images, containers, networks, volumesHead chef
containerdManages each container's life (start, stop, pause)Supervisor watching the degs
runcAsks the kernel to create the container, then exitsCook who lights the flame and walks away
RegistryStores imagesWholesale market

On Windows: containers need a Linux kernel. Docker Desktop runs dockerd inside a light Linux VM using WSL2. Run docker version: Client says windows, Server says linux.

Concept 4

Docker Image & Docker Container

Image: a read-only template containing the app, its runtime, libraries and the start command. It never changes.

Container: a running instance of an image. Docker adds a thin writable layer on top. One image can create many containers. (OOP: image = class, container = object.)

🍲
The image is the sealed master deg. Each container is a serving counter served from it, with its own plate. Ten counters, one deg.

Concept 5

Base image

The image you start from, written in the first line of the Dockerfile: FROM node:20-alpine. It gives you an OS and a runtime, so you only add your app on top. Alpine variants are tiny; slim variants are small; plain tags are big.

🍲
You don't grow your own rice. You buy ready base rice from the market and put your masala and garnish on top. Choose fine rice and the whole deg is lighter.

Concept 6

Docker Registry

A registry stores and shares images. Docker Hub is the default public one. Others: GitHub Container Registry (ghcr.io), AWS ECR, or a private one. A repository holds all versions of one image; a tag is a version.

When you run an image, dockerd first checks your local images. Only if it is missing does it download it from the registry.

🍲
The head chef first checks the pantry. Rice is there? Use it. Not there? Send someone to the market. Market closed (no internet) and pantry empty? No biryani today.

Concept 7

Layered filesystem

An image is a stack of read-only layers. Each Dockerfile instruction (FROM, COPY, RUN) adds one layer. Layers give three benefits: caching, sharing and copy-on-write.

🍲
A deg is built in tehein: base rice, masala, more rice, garnish. If only the garnish changes, you don't cook the whole deg again. Two degs can share the same base rice. Raita goes on your plate, never into the deg.

Concept 9

Volumes

The writable layer dies with the container. A volume stores data outside the container so it survives docker rm.

🍲
After the event the deg is washed and anything inside is gone. The smart cook keeps the yakhni pateela in the store room. Tomorrow's new deg uses the same yakhni.

Concept 10

Container lifecycle

A container moves through states: Created → Running → Paused → Exited → Removed. docker run = create + start. A container keeps running only while its main process (CMD) runs.

🍲
Created: deg filled, stove off. Running: on the flame, serving. Paused: on dum, everything frozen in place. Exited: flame off, deg still in the kitchen. Removed: deg washed.

docker rmDeletes container + writable layer (image safe)Wash the deg

Hands-on

$ docker run -d -p 8080:80 --name web nginx $ docker pause web $ docker unpause web $ docker stop web $ docker ps -a $ docker start web $ docker rm -f web
