Docker on Windows from scratch: install, build and run a frontend container

Start with a Windows PC that has nothing installed. By the end you will have WSL2, Ubuntu and Docker Desktop working, and your own website running inside a container.

⏱ Part 1: 40 to 60 min (downloads + restarts)⏱ Part 2: 30 min⏱ Part 3 (bonus): 20 min🌐 Internet required🔑 Administrator rights required
Part 1: InstallPart 2: Frontend containerPart 3: React (bonus)TroubleshootingCheat sheet

What we are installing, and why

Containers need a Linux kernel. Windows does not have one, so we add one with WSL2. Docker Desktop then runs the Docker Engine on top of it.

Each command block is marked with where to run it: PowerShell (Administrator) PowerShell Ubuntu terminal Inside a container

Part 1

Install WSL2, Ubuntu and Docker Desktop

1

Check your Windows version and RAM

Press Win + R, type winver, press Enter.

  • Windows 11, or Windows 10 version 22H2 (build 19045) or newer
  • 64-bit: Settings → System → About → System type
  • RAM: 4 GB minimum, 8 GB recommended (same About page)
⚠ Older Windows 10? Run Windows Update first and install all updates.
2

Check that CPU virtualization is enabled

  1. Press Ctrl + Shift + Esc to open Task Manager
  2. Go to Performance → CPU
  3. Bottom right: Virtualization: Enabled
✔ Enabled: continue to step 3.
⚠ Disabled: restart the PC and open the BIOS/UEFI (usually F2, F10, Del or Esc while booting). Turn on Intel VT-x / Intel Virtualization Technology or AMD SVM. Save and exit. On lab PCs, ask the lab administrator.
3

Enable WSL and Virtual Machine Platform

Do either Option A (GUI) or Option B (command line). Both do the same thing.

OPTION A: GUI
  1. Click Start and type Turn Windows features on or off, then open it
  2. Tick Virtual Machine Platform
  3. Tick Windows Subsystem for Linux
  4. Click OK, wait, then click Restart now
OPTION B: Command line

Click Start, type PowerShell, right-click it and choose Run as administrator.

PowerShell (Administrator) 
dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart
dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
The operation completed successfully.

Then restart the computer.

Why two features? Windows Subsystem for Linux lets Windows run Linux programs. Virtual Machine Platform lets WSL2 run a real Linux kernel in a lightweight virtual machine.
4

Update WSL and make version 2 the default

After the restart, open PowerShell as Administrator again.

PowerShell (Administrator) 
wsl --update
wsl --set-default-version 2
wsl --version
✔ wsl --version prints a WSL version and a kernel version.
WSL1 vs WSL2: WSL1 translated Linux calls into Windows calls. WSL2 runs a real Linux kernel, which Docker needs.
5

Install a Linux distribution (Ubuntu)

PowerShell (Administrator) 
wsl --list --online
wsl --install -d Ubuntu

An Ubuntu window opens. Create a username (lowercase, no spaces) and a password. While typing the password nothing appears on screen; that is normal.

Installing, this may take a few minutes... Enter new UNIX username: ali New password: Retype new password: passwd: password updated successfully

Type exit to close Ubuntu. Then check in PowerShell:

PowerShell 
wsl -l -v
NAME STATE VERSION * Ubuntu Stopped 2
✔ Ubuntu is listed with VERSION 2.
⚠ Shows VERSION 1? Run wsl --set-version Ubuntu 2
6

Download and install Docker Desktop

  1. Open https://www.docker.com/products/docker-desktop/
  2. Click Download for Windows – AMD64. Use the ARM64 version only on ARM laptops (for example Snapdragon). The file is about 500 to 600 MB.
  3. Run Docker Desktop Installer.exe and click Yes when Windows asks for permission
  4. On the Configuration screen keep Use WSL 2 instead of Hyper-V (recommended) ticked
  5. Click OK and wait for the installation
  6. Click Close and restart (or sign out and back in if asked)
⚠ The installer adds the installing user to the docker-users group. If a different Windows account will use Docker, see "not allowed to use Docker" in Troubleshooting.
7

Start Docker Desktop and connect it to Ubuntu

  1. Open Docker Desktop from the Start menu
  2. Accept the service agreement
  3. Sign-in and survey screens: you can click Skip
  4. Wait until the bottom-left shows Engine running (green) and the whale icon in the taskbar stops animating
  5. Open Settings (gear icon) → Resources → WSL integration
  6. Switch on Ubuntu, then click Apply & restart
What just happened? Docker Desktop created its own small Linux system inside WSL2 and started the Docker Engine (dockerd) there. WSL integration also lets you use the docker command from Ubuntu.
8

Verify the installation

Open a normal PowerShell (not Administrator).

PowerShell 
docker --version
docker version
docker run hello-world
Hello from Docker! This message shows that your installation appears to be working correctly. To generate this message, Docker took the following steps: 1. The Docker client contacted the Docker daemon. 2. The Docker daemon pulled the "hello-world" image from the Docker Hub. 3. The Docker daemon created a new container from that image ... 4. The Docker daemon streamed that output to the Docker client ...
✔ docker version shows Client (OS/Arch: windows) and Server (OS/Arch: linux), and hello-world prints "Hello from Docker!"

Also check from Ubuntu:

PowerShell 
wsl -d Ubuntu
Ubuntu terminal 
docker --version
exit
Read the hello-world output carefully. It describes the Docker architecture: the client (CLI) talks to the daemon, the daemon pulls the image from the registry (Docker Hub), creates a container and sends the output back.

Build and run a frontend container

9

Create the project folder

Write the frontend

index.html
<!DOCTYPE html>

</body>
</html>
style.css

  background: #f4f6fb;
  display: flex;

  border-radius: 12px;

11

Write the Dockerfile

Create a file named exactly Dockerfile: capital D, no extension.

Dockerfile
# Base image: a small Linux (Alpine) with the nginx web server
FROM nginx:alpine

# Copy our website into the folder nginx serves
COPY . /usr/share/nginx/html

# nginx listens on port 80 inside the container
EXPOSE 80
InstructionMeaning
FROM nginx:alpineStart from the base image nginx (web server) on Alpine Linux
COPY . /usr/share/nginx/htmlCopy all files in this folder into nginx's website folder. Creates a new layer.
EXPOSE 80Documents that the app uses port 80. It does not open the port; -p does that.

No CMD line is needed: the nginx base image already starts nginx.

Also create .dockerignore so these files are not copied into the image:

.dockerignore
Dockerfile
.dockerignore
.git
⚠ Notepad users: in Save As, choose Save as type: All Files, otherwise Windows saves Dockerfile.txt. Check the real names with dir in PowerShell.
12

Build the image

PowerShell (inside C:\docker-lab\my-frontend) 
docker build -t my-frontend:1.0 .

-t my-frontend:1.0 sets the image name and tag (version). The final dot is the build context: "use the files in this folder". Don't forget it.

[+] Building 6.2s (7/7) FINISHED => [internal] load build definition from Dockerfile => [1/2] FROM docker.io/library/nginx:alpine ← downloaded from Docker Hub => [2/2] COPY . /usr/share/nginx/html => naming to docker.io/library/my-frontend:1.0
docker images
docker history my-frontend:1.0
✔ my-frontend with tag 1.0 appears. docker history shows its layers, with your COPY layer on top.
13

Run the container

PowerShell 
docker run -d -p 8080:80 --name frontend my-frontend:1.0
FlagMeaning
-dDetached: run in the background and keep the terminal free
-p 8080:80Port mapping: your PC's port 8080 → container's port 80
--name frontendA readable name instead of a random one
my-frontend:1.0The image to create the container from
docker ps
CONTAINER ID IMAGE STATUS PORTS NAMES 4f2a9c71b8e0 my-frontend:1.0 Up 5 seconds 0.0.0.0:8080->80/tcp frontend

If Windows Firewall shows a popup, click Allow.

14

Open it in the browser

Go to http://localhost:8080

✔ You see "UCP Student Portal, Version 1.0" with three students. Your first container is running. 🎉

You can also see it in Docker Desktop → Containers. Click the 8080:80 link there.

15

Look inside the container

PowerShell 
docker logs frontend
docker exec -it frontend sh

The prompt changes to / #. You are now inside the container:

Inside the container 
ls /usr/share/nginx/html
cat /etc/os-release
exit
Your PC runs Windows, but inside the container it is Alpine Linux. The container uses the Linux kernel provided by WSL2.
16

Change the code and release version 2.0

In index.html change Version 1.0 to Version 2.0 and add a fourth student. Save, then:

PowerShell 
docker build -t my-frontend:2.0 .
docker rm -f frontend
docker run -d -p 8080:80 --name frontend my-frontend:2.0

Refresh the browser (Ctrl + F5): Version 2.0.

Layer caching: in the build output, FROM nginx:alpine is CACHED. Docker did not download it again; only the changed COPY layer was rebuilt.
⚠ Editing a file does not change a running container. Images are read-only: build a new image, then run a new container from it.
17

One image, many containers

PowerShell 
docker run -d -p 8081:80 --name frontend2 my-frontend:2.0
docker run -d -p 8082:80 --name frontend3 my-frontend:2.0
docker ps

Open localhost:8081 and localhost:8082. One image, three separate containers, each with its own ID and port.

18

Practice the container lifecycle

PowerShell 
docker pause frontend2
docker ps
docker unpause frontend2
docker stop frontend2
docker ps -a
docker start frontend2

19

Clean up

PowerShell 
docker rm -f frontend frontend2 frontend3
docker ps -a
docker images
✔ The containers are gone, but my-frontend:1.0 and 2.0 are still listed. Removing a container never deletes its image.
Part 3 (bonus)

React frontend with a multi-stage build

A React app must first be built (npm run build) into plain HTML, CSS and JS. Stage 1 does this in a Node container. Stage 2 copies only the result into nginx. You still don't need Node.js on your PC.

20

Create the React project files

PowerShell 
mkdir C:\docker-lab\react-frontend\src
cd C:\docker-lab\react-frontend
code .
react-frontend/ ├── package.json ├── vite.config.js ├── index.html ├── src/ │ ├── main.jsx │ └── App.jsx ├── .dockerignore └── Dockerfile
package.json
{
  "name": "my-react-frontend",
  "private": true,
  "version": "1.0.0",
  "type": "module",
  "scripts": {
    "dev": "vite",
    "build": "vite build"
  },
  "dependencies": {
    "react": "^18.3.1",
    "react-dom": "^18.3.1"
  },
  "devDependencies": {
    "@vitejs/plugin-react": "^4.3.1",
    "vite": "^5.4.0"
  }
}
vite.config.js
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'

export default defineConfig({
  plugins: [react()]
})
index.html
<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <title>UCP Student Portal</title>
  </head>
  <body>
    <div id="root"></div>
    <script type="module" src="/src/main.jsx"></script>
  </body>
</html>
src/main.jsx
import React from 'react'
import ReactDOM from 'react-dom/client'
import App from './App.jsx'

ReactDOM.createRoot(document.getElementById('root')).render(<App />)
src/App.jsx
import { useState } from 'react'

export default function App() {
  const [count, setCount] = useState(0)
  return (
    <div style={{ fontFamily: 'Arial', textAlign: 'center', marginTop: 60 }}>
      <h1>UCP Student Portal (React)</h1>
      <p>Built inside a Node container, served by nginx.</p>
      <button onClick={() => setCount(count + 1)}>Clicked {count} times</button>
    </div>
  )
}
21

Write the multi-stage Dockerfile

Dockerfile
# ---------- Stage 1: build the React app ----------
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
RUN npm run build

# ---------- Stage 2: serve the build with nginx ----------
FROM nginx:alpine
COPY --from=builder /app/dist /usr/share/nginx/html
EXPOSE 80
.dockerignore
node_modules
dist
InstructionMeaning
AS builderNames the first stage so the second stage can refer to it
COPY package*.json ./ before COPY . .Keeps the slow npm install layer cached when only your code changes
COPY --from=builderTakes only the dist folder from stage 1; everything else in stage 1 is discarded
22

Build, run and compare

PowerShell (inside C:\docker-lab\react-frontend) 
docker build -t react-frontend:1.0 .
docker run -d -p 3000:80 --name react-web react-frontend:1.0
docker images

Open http://localhost:3000 and click the button.

✔ react-frontend is much smaller than node:20-alpine, because Node.js and node_modules are not in the final image.
⚠ The first build needs internet: Docker pulls node and nginx from Docker Hub, and npm install downloads packages from the npm registry.

Troubleshooting

Installation

ProblemCause and fix
Error 0x80370102 or "virtualization not enabled"CPU virtualization is off. Enable VT-x / SVM in BIOS (step 2).
Error 0x8007019eThe WSL feature is not enabled. Repeat step 3 and restart.
"WSL 2 requires an update to its kernel component"Run wsl --update in PowerShell (Administrator).
wsl --install only prints help textWSL is already installed. Use wsl --install -d Ubuntu.
Docker Desktop stuck on "Engine starting"Check step 2 and step 4 (wsl --version). Restart the PC. Then Docker Desktop → Troubleshoot (bug icon) → Restart.
"You are not allowed to use Docker, you must be in the docker-users group"In PowerShell (Administrator): net localgroup docker-users "YOUR-USERNAME" /add, then sign out and back in.
docker: The term 'docker' is not recognizedClose and reopen PowerShell after installing. If it continues, restart the PC.

Building and running

ProblemCause and fix
error during connectDocker Desktop is closed or still starting. Open it and wait for Engine running.
failed to read dockerfileThe file is Dockerfile.txt or misspelled. Rename it to Dockerfile.
"docker build" requires exactly 1 argumentYou forgot the final dot: docker build -t my-frontend:1.0 .
port is already allocatedPort 8080 is in use. Use another one, for example -p 8090:80, and open localhost:8090.
container name "/frontend" is already in useRemove the old container: docker rm -f frontend
Page shows "Welcome to nginx!"Your files were not copied. Check the COPY line and that index.html is in the same folder as the Dockerfile.
Changes don't appearBuild a new image and run a new container (step 16), then press Ctrl + F5.
npm ERR! during React buildUsually a typo in package.json (missing comma or quote) or no internet.
